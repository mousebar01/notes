# AKS 自适应关键帧采样方法

> 来源：论文 *Adaptive Keyframe Sampling for Long Video Understanding* 的个人整理；论文版本、作者与正式链接待补充。
>
> 采用状态：长视频理解候选方法，未纳入当前 `storyboard -> retrieval -> trim -> 拼接` 主线。
>
> 验证状态：尚未记录实现、基线对比或实际运行结果；阈值方向和伪代码采用前需重新对照论文。

这篇论文的核心方法叫 **AKS：Adaptive Keyframe Sampling**，目标是在长视频输入受限时，给 MLLM 选出更有用的关键帧，而不是简单均匀采样。论文把它设计成一个 **plug-and-play 的前处理模块**：先从长视频里选关键帧，再把这些帧送进现有视频 MLLM，不需要重新训练模型。

## 1. 问题：长视频 token 太多，只能选少量帧

视频 MLLM 通常会把视频帧编码成视觉 token，再和文本问题一起输入 LLM。但长视频的帧数太多，视觉 token 会超过模型上下文容量，所以只能选固定数量的帧，比如 32 或 64 帧。

已有方法常用 **Uniform Sampling**，即均匀抽帧。但问题是：关键事件可能只出现在很短时间段内，均匀采样很容易错过。论文第一页的例子就是：问题问熊猫在做什么，均匀采样选到的帧不相关，模型答错；AKS 选到了真正相关的关键帧，答对了。

## 2. AKS 的两个原则：相关性 + 覆盖性

论文认为，好的关键帧集合应该同时满足两个条件：

**第一，Relevance：与问题相关。**
每一帧都应该尽量包含回答问题所需的信息。比如问题是“太阳在视频中出现了几次”，那么和太阳相关的帧应该得分更高。

**第二，Coverage：覆盖整段视频。**
关键帧不能全部集中在一个小时间段，否则可能漏掉其他重要时刻。尤其是一些问题需要跨多个时间点统计或理解，比如“某个动作出现了几次”“主角换了几套衣服”。

因此论文把关键帧选择写成一个优化目标：

> 选出 M 个帧，使得它们的总相关性高，同时在时间轴上的覆盖性也好。

也就是在 **“挑最相关的帧”** 和 **“不要全挤在一起”** 之间做平衡。

## 3. 怎么计算“相关性”？

AKS 不直接用目标 MLLM 来给每帧打分，因为那样太贵。它使用一个较轻量的视觉语言模型，比如 **BLIP** 或 **CLIP**，计算文本问题 Q 和每一帧 Ft 的 image-text matching 分数：

[
s(Q, F_t)
]

这个分数表示：第 t 帧和当前问题有多相关。

实际流程是：先以较低频率从原视频中取候选帧，比如每秒 1 帧；然后把问题和候选帧送入 BLIP，得到每一帧的问题相关性分数。

## 4. 怎么估计“覆盖性”？

论文没有直接用复杂的全局覆盖度计算，而是用了一个递归分桶思想。

直观理解是：

先把整段视频分成左右两个时间区间，看看关键帧是不是都集中在一边。如果分布太不均衡，就说明覆盖性差。然后继续把每个区间再分成更小的区间，递归判断。

这类似于在时间轴上做层级划分：

* Level 0：整段视频；
* Level 1：分成 2 个 bin；
* Level 2：每个 bin 再分成 2 个；
* 继续递归直到最大深度 L。

如果关键帧分布过度集中，coverage 项会惩罚这种情况。

## 5. 三种采样策略：TOP、BIN、ADA

论文先讨论两个极端策略，然后提出最终的自适应策略。

### TOP：只看相关性

直接选 image-text matching 分数最高的 M 帧。

优点是能抓住和问题最相关的瞬间。
缺点是这些帧可能都来自同一个短片段，导致覆盖不足。

适合：问题只依赖某一个局部时刻，比如“这个人此时在做什么”。

### BIN：强制覆盖

把视频分成多个时间 bin，每个 bin 里选分数最高的帧。

优点是覆盖更均匀，不容易漏掉不同时间段的信息。
缺点是如果真正相关的信息集中在某个片段，BIN 会浪费名额在不相关区间。

适合：问题需要跨多个片段，比如“总共出现了几次”。

### ADA：自适应采样，也就是 AKS 的核心

ADA 会递归地判断当前时间区间到底应该：

* 直接选 top-M 高分帧；
* 还是继续分裂成子区间，让关键帧分布更均匀。

判断依据是：当前区间里 top-M 帧的平均分数和整体平均分数差距是否足够大。

如果 top-M 明显高很多，说明这些高分帧很重要，就直接选它们。
如果差距不明显，说明不能只相信局部高分，需要继续分桶来保证覆盖。

所以 ADA 本质上是在 **TOP 和 BIN 之间动态切换**。

## 6. AKS 的完整流程

可以把方法概括成 5 步：

1. 从长视频中按固定频率抽取候选帧，比如 1 fps。
2. 用 BLIP/CLIP 等视觉语言模型计算每个候选帧和问题的匹配分数。
3. 从整段视频开始，递归执行 judge-and-split：

   * 如果某一区间里高分帧足够突出，就直接选 top 帧；
   * 否则把该区间继续拆成两个子区间。
4. 直到选够固定数量 M 个关键帧，比如 32 或 64。
5. 把这些关键帧输入原本的视频 MLLM，例如 Qwen2-VL、LLaVA-OV、LLaVA-Video。

## 7. 方法的核心贡献

我觉得这篇论文的方法贡献主要有三点：

第一，它指出长视频理解中 **“选哪些帧”** 本身就是一个关键问题，而不是简单的工程细节。

第二，它把关键帧选择明确建模为 **相关性 + 覆盖性** 的权衡，而不是只做均匀采样或只取最高分帧。

第三，它提出了一个轻量、无需训练、可插拔的算法，可以直接加到已有视频 MLLM 前面，提高长视频问答效果。

一句话总结：**AKS 不是改 MLLM，而是让 MLLM 看到更该看的帧。**

总的流程
AKS(video, question, M):

1. 从视频中按固定频率抽候选帧
2. 用 BLIP/CLIP 计算每一帧和 question 的相关性分数
3. 对整段视频调用 ADA(区间, M)

ADA(当前区间, 当前需要选的帧数 m):

    计算当前区间所有帧的平均分 s_all
    计算当前区间 top-m 帧的平均分 s_top

    如果 m == 1:
        返回当前区间最高分帧

    如果 s_top - s_all > 阈值 s_thr:
        返回当前区间 top-m 高分帧

    否则:
        把当前区间切成左右两个子区间
        左边选 m/2 帧，右边选 m/2 帧
        分别递归调用 ADA
        合并左右结果并返回
