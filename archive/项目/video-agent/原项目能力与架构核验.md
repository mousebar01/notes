## 编排架构核验

旧笔记描述的架构是：统一入口接受需求，`MultiAgent` 使用意图表和 Agent 元数据设计 DAG，再由执行器动态加载 Agent，通过共享 `context` 传递上下游数据。

## 当前采用的收缩方案

暂定主线不需要先证明“任意需求都能生成正确 Agent DAG”。第一阶段只保留可单独验收的固定链路：

```text
用户需求
  -> 结构化 storyboard
  -> 从素材库检索候选片段
  -> 按时间范围 trim
  -> 顺序拼接
  -> 检查最终视频可解码、时长和片段来源
```

这一选择来自 [工程落地复盘](./视频智能体论文工程落地复盘.md)，仍待作者最终确认。当前文档也不能证明这条链已经在现有环境端到端跑通；完成标准应是保留一条可复现命令、固定测试素材、逐步产物和最终成片。
