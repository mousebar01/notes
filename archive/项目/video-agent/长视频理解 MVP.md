# 长视频理解 MVP

本文把原来的长视频理解系统方案收缩为一个可实现、可评测的最小版本。完整建议与功能头脑风暴保存在 `archive/projects/video-agent/长视频理解系统需求设计-原稿.md`。

> 状态：候选方向，尚未确认进入实现
>
> 整理日期：2026-07-13
>
> 核心原则：字幕优先、ASR 补全、视觉兜底、答案必须能回到时间戳证据

## 目标

输入一个长视频，系统完成一次后台解析，并提供：

1. 带时间范围的章节与摘要。
2. 围绕单个视频的自然语言问答。
3. 每个事实性回答都附可定位的字幕、ASR 或画面证据。
4. 当某种模态不可用时，明确降级并提示置信度来源。

MVP 的价值不在“能谈论视频”，而在“回答可以被用户点击时间戳复核”。

## 范围

### 包含

- 单视频上传或本地文件输入。
- 元信息、字幕轨和音轨检测。
- 字幕提取、清洗、切块与质量判断。
- 字幕缺失或覆盖不足时的 ASR。
- 粗粒度场景抽帧；问题确实需要画面时再做 OCR 或 caption。
- 字幕、ASR、OCR 和帧描述的统一索引。
- 多路召回、时间邻域扩展、重排和证据聚合。
- 摘要、章节、问答与可点击时间戳。
- 后台任务状态、基础缓存和失败信息。

### 不包含

- 多视频知识库和跨视频比较。
- 知识图谱、思维导图和学习卡片。
- 通用多 Agent 动态规划。
- 全视频逐帧 VLM 分析。
- 说话人分离、情绪识别和 UI 操作理解。
- 自动剪辑、配音或视频生成。

这些能力保留在 [功能候选 Backlog](./功能候选%20Backlog.md)，不进入 MVP 验收。

## 用户链路

```text
提交视频
  -> 校验并创建解析任务
  -> 提取字幕；必要时运行 ASR
  -> 粗采样画面并建立统一证据索引
  -> 生成章节与摘要
  -> 用户提问
  -> 多路召回 + 时间邻域扩展 + 重排
  -> 返回答案、证据和时间戳
```

视频解析必须异步执行。问答只能在最小文本索引可用后开放；视觉索引可以作为后续阶段补齐，但接口要标明当前索引状态。

## 处理链路

### 1. 输入与元信息

解析时长、分辨率、帧率、编码、字幕轨、音轨和文件 hash。hash 用于缓存复用，输入文件保存在任务隔离目录。

### 2. 字幕优先

字幕来源优先级：人工外挂字幕、内嵌字幕、自动字幕、ASR、OCR / 画面描述。

字幕质量至少检查：是否为空、时间轴是否可解析、重复率、语言、覆盖率和异常字符。具体阈值应通过样本基线确定，当前待实测，不在文档中预设一个看似精确的数字。

### 3. ASR 补全

字幕缺失、覆盖不足或质量不合格时，提取单声道音频并运行 VAD 与 ASR。ASR 输出必须保留开始时间、结束时间、文本和模型置信信息；专有名词修正不能覆盖原始转写。

### 4. 视觉兜底

先做均匀或场景变化采样，避免默认逐帧调用 VLM。只有以下情况进入更细视觉处理：

- 视频没有有效字幕和语音。
- 用户问题包含“画面中”“图表”“代码”“界面”等视觉意图。
- 文本证据不足以回答。
- 召回到某个时间段后需要补充相邻画面。

OCR、图像 caption 和问题相关采样均属于可选步骤。AKS 可作为后续候选，采用前需核对论文算法并做基线比较。

### 5. 统一证据索引

字幕、ASR、OCR 和帧描述使用同一最小结构：

```json
{
  "id": "video_001_asr_00042",
  "video_id": "video_001",
  "source_type": "subtitle | asr | ocr | frame_caption",
  "start_time": 120.0,
  "end_time": 138.5,
  "text": "这一段证据文本",
  "asset_uri": "job://artifacts/frame_000120.jpg",
  "confidence": null,
  "model": "待运行时记录"
}
```

`start_time` 和 `end_time` 是一等字段，不能只塞进不可查询的 metadata。每条派生结果都要保留来源 ID，便于回溯到原始字幕、转写或画面。

### 6. 检索与回答

```text
问题分类 / 改写
  -> 字幕、ASR、OCR、帧描述多路召回
  -> 合并重复证据
  -> 扩展命中点前后的时间邻域
  -> 重排
  -> 证据压缩
  -> 基于证据回答
```

回答不得把模型常识伪装成视频事实。证据不足时返回“当前证据无法确认”，并指出缺少的是字幕、音频还是画面信息。

## 输出约定

问答返回至少包含：

```json
{
  "answer": "视频中的结论……",
  "confidence": "high | medium | low",
  "evidence": [
    {
      "evidence_id": "video_001_subtitle_00018",
      "source_type": "subtitle",
      "start_time": 72.0,
      "end_time": 95.0,
      "quote": "对应的原始证据",
      "preview_uri": null
    }
  ],
  "limitations": []
}
```

置信度首先反映证据完整性和跨模态一致性，不应直接展示模型未经校准的概率。

## 降级策略

| 情况 | MVP 行为 |
| --- | --- |
| 无字幕 | 使用 VAD + ASR，并在结果中标明来源 |
| 字幕覆盖不足 | 保留原字幕，对缺口补 ASR，不静默覆盖 |
| 无音轨或语音占比低 | 转为视觉优先，并提示回答依据受限 |
| ASR 置信度低 | 保留低置信标记；必要时提示用户复核，不编造纠正结果 |
| 视频过长 | 分段解析、分段建索引，最终合并时间轴 |
| VLM 成本或延迟过高 | 先用文本与轻量相似度召回，只分析 top frames |
| OCR / caption 失败 | 文本问答仍可用，视觉相关问题明确不可回答 |
| 索引中断 | 复用已验收产物；断点恢复实现状态仍需按任务系统单独核验 |
| 字幕与音频冲突 | 同时保留两份证据，优先人工字幕并显示冲突 |

## 评测与验收

先固定一组包含课程、访谈、录屏和弱语音视频的样本，再记录基线。阈值应由这组样本确定，当前均为待实测。

### 功能验收

- 同一视频重复解析能复用有效缓存。
- 章节、摘要和问答中的时间戳可以跳转到正确片段。
- 事实性回答至少绑定一条证据；没有证据时明确拒答。
- 无字幕、无音频和解析失败均有可理解的降级结果。
- 原始证据、派生文本和模型信息可以追溯。

### 质量指标

- 检索：Recall@K、MRR / NDCG、相关时间段命中率。
- 问答：答案正确性、证据支持率、幻觉率、引用时间戳准确率。
- 多模态：视觉证据命中率、字幕 / ASR / 画面一致性。
- ASR：有标注样本上的 WER / CER 与时间戳偏移。
- 摘要与章节：关键信息覆盖率、边界时间偏移。

### 工程指标

- 每小时视频的解析耗时与失败率。
- 首次可问答时间和单次问答延迟。
- ASR、OCR、caption、embedding 与生成模型的分项成本。
- 峰值内存 / 显存和每小时视频的存储占用。

## 安全与隐私

- 限制上传大小、时长和格式，使用媒体探测结果而不是只信扩展名。
- ffmpeg 参数使用结构化进程调用，不拼接未经校验的 shell 字符串。
- 每个任务使用隔离目录，规范化路径并阻止越界访问。
- 字幕、OCR 和视频内文字都视为不可信数据，不能因此触发工具调用或改变系统指令。
- 模型与外部二进制记录来源、版本和 checksum。
- 支持本地处理模式；调用外部模型前明确数据外传范围。
- 对原视频、抽帧和临时音频设置可配置保留期，并提供彻底删除能力。
- 日志不记录完整敏感内容、访问令牌或未经脱敏的用户路径。

## 最小接口

```text
POST /videos                 创建视频记录并上传
POST /videos/{id}/analyze    启动或继续解析任务
GET  /videos/{id}/status     查询各索引阶段状态
GET  /videos/{id}/summary    获取摘要与章节
POST /videos/{id}/qa         提问并返回证据
GET  /videos/{id}/evidence/{evidence_id}
                             获取证据与预览定位
```

具体 Web 框架、向量库和模型后端暂不写死。先用本地样本证明数据结构、证据链和降级行为，再决定部署组件。

## 待确认

- 这条候选方向是否替代、并行于或暂缓于当前视频剪辑主线。
- MVP 首批目标视频类型和最长时长。
- 是否允许视频或抽帧发送到外部模型 API。
- 视觉索引是首轮解析必需项，还是按问题延迟构建。
- 基线样本、质量阈值和成本上限。
