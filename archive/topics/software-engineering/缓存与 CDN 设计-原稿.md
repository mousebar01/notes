# 缓存与 CDN 设计

## 1. 网页静态缓存是什么

网页静态缓存是指把网页中不经常变化的内容提前保存起来，用户下次访问时直接读取缓存，而不是每次都重新请求服务器、查询数据库或重新生成页面。

常见的静态缓存内容包括：

* HTML 页面
* CSS 文件
* JavaScript 文件
* 图片
* 字体
* 视频
* 已经生成好的页面片段

它的主要作用是：

* 提高访问速度
* 减轻服务器压力
* 提升网站并发能力
* 降低服务器资源消耗

简单来说：

> 网页静态缓存就是把不常变化的网页内容提前保存起来，下次访问时直接使用。

---

## 2. 缓存过期时间一般多久

缓存过期时间没有固定标准，需要根据资源类型来设置。

一般规则是：

> 页面缓存短一点，静态资源缓存长一点；带版本号或 hash 的资源可以缓存很久。

常见设置如下：

| 资源类型                  | 常见缓存时间          |
| --------------------- | --------------- |
| HTML 页面               | 几秒到几分钟          |
| 新闻、文章详情页              | 5 分钟到 1 小时      |
| CSS / JS 文件           | 几天到 1 年         |
| 带版本号或 hash 的 CSS / JS | 6 个月到 1 年       |
| 图片、字体等静态资源            | 7 天到 1 年        |
| CDN 静态资源              | 几分钟到几天，稳定资源可以更久 |

例如：

```nginx
location ~* \.(css|js|png|jpg|jpeg|gif|webp|svg|ico|woff2?)$ {
    expires 30d;
    add_header Cache-Control "public";
}
```

如果文件名带 hash，例如：

```text
app.a8f3c9.js
style.7fd21a.css
```

可以设置更长时间：

```nginx
expires 365d;
add_header Cache-Control "public, immutable";
```

## 3. 内容更新后如何确保缓存也更新

当网站内容更新后，需要让旧缓存失效，否则用户可能看到旧内容。

常见做法有以下几种：

### 3.1 文件名加版本号或 hash

例如原来是：

```html
<link rel="stylesheet" href="/css/style.css">
```

更新后变成：

```html
<link rel="stylesheet" href="/css/style.a8f3c9.css">
```

浏览器和 CDN 会认为这是一个新文件，从而重新下载最新资源。

这种方式叫：

> 缓存破坏，英文叫 Cache Busting。

---

### 3.2 URL 后面加版本参数

例如：

```html
<script src="/js/app.js?v=20260701"></script>
```

更新后改成：

```html
<script src="/js/app.js?v=20260702"></script>
```

这样浏览器会把它当成新的 URL，重新请求最新文件。

不过实际项目中，更推荐使用文件名 hash。

---

### 3.3 清理服务器缓存

如果服务器缓存了静态 HTML 页面，例如：

```text
/cache/news/123.html
```

当文章内容更新后，需要删除对应旧缓存。

流程可以理解为：

```text
文章更新
→ 删除旧缓存
→ 下次访问时重新生成新缓存
```

---

### 3.4 主动刷新 CDN 缓存

如果资源已经被 CDN 缓存，更新后可以在 CDN 控制台或通过接口执行刷新缓存操作。

常见方式有：

* 刷新指定 URL
* 刷新目录
* 刷新全站缓存

例如刷新：

```text
https://example.com/news/123.html
```

---

### 3.5 HTML 页面不要缓存太久

HTML 页面通常是入口页面，里面会引用最新的 CSS 和 JS 文件。

所以 HTML 页面一般缓存时间较短，或者设置：

```http
Cache-Control: no-cache
```

`no-cache` 不是完全不缓存，而是表示每次使用缓存前，都要向服务器确认是否有更新。

## 4. 这个属于后端内容吗

网页静态缓存通常属于后端相关内容，但也会涉及前端和运维。

更准确地说，它属于：

> Web 性能优化 / 缓存机制

不同角色关注点不同：

| 方向          | 是否相关 | 说明                          |
| ----------- | ---- | --------------------------- |
| 后端          | 很相关  | 控制 HTML 页面缓存、接口缓存、缓存失效逻辑    |
| 前端          | 相关   | 处理 CSS、JS、图片的版本号、hash、浏览器缓存 |
| 运维 / DevOps | 很相关  | 配置 Nginx、CDN、缓存过期时间、刷新 CDN  |
| 数据库         | 间接相关 | 缓存可以减少数据库查询压力               |

简单理解：

> 静态资源缓存偏前端和运维；页面缓存、接口缓存、缓存失效策略偏后端。

---

## 5. 人们为什么会想到缓存

缓存的思想来自一个很简单的规律：

> 很多东西会被反复使用，但每次都重新获取或重新计算太浪费。

所以人们想到：

> 第一次拿到结果后，先保存起来；下次再要同样的东西，就直接使用保存好的。

生活中的例子：

* 电话号码存在通讯录里，下次不用重新问别人
* 餐厅提前煮好米饭，客人点餐时直接盛
* 常用文件放在桌面，不用每次都去深层文件夹找

计算机中也是一样。

因为 CPU、内存、硬盘、网络、数据库的速度差异很大，所以如果某些数据经常被访问，就没必要每次都从最慢的地方重新获取。

缓存的核心思想是：

> 用空间换时间。

也就是多占用一点存储空间，把结果先保存起来，换取更快的访问速度。

但是缓存也会带来一个问题：

> 缓存里的内容可能会过期。

所以才需要设置：

* 缓存多久过期
* 什么时候清缓存
* 内容更新后怎么让缓存失效
* 如何判断缓存是不是最新

## 6. 浏览器缓存是什么

浏览器缓存是指把资源保存在用户自己的电脑或手机上。

例如用户第一次访问网站时，浏览器下载了：

* CSS 文件
* JS 文件
* 图片
* 字体

下次再访问同一个网站时，如果这些资源没有过期，浏览器就可以直接从本地读取，不需要重新下载。

浏览器缓存的特点是：

| 特点     | 说明            |
| ------ | ------------- |
| 缓存位置   | 用户电脑或手机       |
| 使用者    | 同一个用户自己的浏览器   |
| 主要缓存内容 | CSS、JS、图片、字体等 |
| 主要作用   | 减少重复下载，提高访问速度 |

一句话总结：

> 浏览器缓存就是用户本地存一份资源，下次访问时直接从本地读取。

---

## 7. 服务器缓存是什么

服务器缓存是指缓存不放在用户浏览器里，而是放在网站服务器这一侧。

用户访问网页时，请求会先到服务器。服务器如果发现这个内容之前已经生成过、查过或计算过，就直接把缓存结果返回给用户，不再重新查数据库或重新生成页面。

没有服务器缓存时：

```text
用户访问文章页面
→ 服务器查询数据库
→ 后端拼接 HTML 页面
→ 返回给用户
```

有服务器缓存时：

```text
用户访问文章页面
→ 服务器发现已有缓存
→ 直接返回缓存页面
```

例如一个文章详情页：

```text
/news/123
```

第一次访问时，服务器可能需要：

* 查询文章标题
* 查询文章正文
* 查询作者信息
* 查询评论数量
* 生成 HTML 页面

然后服务器把生成好的结果保存起来。

第二个用户再访问 `/news/123` 时，服务器就可以直接返回保存好的页面。

服务器缓存常见类型：

| 类型   | 例子              | 说明                          |
| ---- | --------------- | --------------------------- |
| 页面缓存 | 缓存整页 HTML       | 适合文章页、新闻页、商品详情页             |
| 数据缓存 | 缓存数据库查询结果       | 比如文章信息、商品信息、用户信息            |
| 接口缓存 | 缓存 API 返回结果     | 比如 `/api/news/123` 的 JSON   |
| 片段缓存 | 缓存页面一部分         | 比如热门文章列表、侧边栏                |
| 文件缓存 | 把缓存写成文件         | 比如生成 `/cache/news/123.html` |
| 内存缓存 | Redis、Memcached | 读取速度很快，常用于后端                |

浏览器缓存和服务器缓存区别：

| 对比     | 浏览器缓存      | 服务器缓存             |
| ------ | ---------- | ----------------- |
| 缓存位置   | 用户电脑或手机    | 网站服务器             |
| 谁来使用   | 同一个用户的浏览器  | 所有访问网站的用户         |
| 主要缓存内容 | CSS、JS、图片等 | HTML、接口数据、数据库查询结果 |
| 主要作用   | 减少用户重复下载   | 减少服务器重复计算和查数据库    |

一句话总结：

> 浏览器缓存是“用户本地存一份”，服务器缓存是“网站服务器提前存一份”。

## 8. 服务器和数据库是分开的吗

服务器和数据库通常可以分开，但不是必须分开。

最简单的网站可能是：

```text
一台机器 = Web 服务器 + 后端程序 + 数据库
```

比如个人博客、小项目，可能全部部署在同一台服务器上。

稍微正规一点的网站通常是：

```text
用户浏览器
   ↓
Web 服务器 / 后端服务器
   ↓
数据库服务器
```

也就是说，后端服务和数据库是两个不同的服务，甚至可能部署在不同机器上。

这有一点分布式的特征，但不一定就是完整意义上的分布式系统。

可以这样理解：

| 架构                          | 算不算分布式    | 说明          |
| --------------------------- | --------- | ----------- |
| 后端和数据库在同一台机器                | 不算        | 单机应用        |
| 后端和数据库分开机器                  | 广义上有分布式特征 | 服务分布在不同机器上  |
| 多台后端服务器 + 数据库 + Redis + CDN | 更像分布式系统   | 多个节点协同工作    |
| 微服务 + 消息队列 + 分布式缓存 + 分库分表   | 典型分布式系统   | 系统被拆成多个独立服务 |

常见网站架构可能是：

```text
用户
 ↓
CDN
 ↓
Nginx
 ↓
后端服务器 A / 后端服务器 B / 后端服务器 C
 ↓
Redis 缓存
 ↓
MySQL 数据库
```

其中：

* CDN 负责静态资源加速
* Nginx 负责反向代理和负载均衡
* 后端服务器负责业务逻辑
* Redis 负责缓存
* MySQL 负责持久化存储

一句话总结：

> 后端服务器和数据库通常可以分开部署；分开部署有分布式特征，但真正的分布式系统通常还会有多台服务器、负载均衡、缓存、消息队列、服务拆分等。

## 9. CDN 是什么

CDN 全称是：

```text
Content Delivery Network
```

中文叫：

```text
内容分发网络
```

它的作用是：

> 把网站的静态资源缓存到离用户更近的服务器节点上，让用户访问更快。

比如网站服务器在北京，用户在广州。

没有 CDN 时：

```text
广州用户 → 北京服务器 → 返回图片 / CSS / JS
```

有 CDN 时：

```text
广州用户 → 广州附近的 CDN 节点 → 返回图片 / CSS / JS
```

这样距离更近，访问速度就更快。

CDN 常缓存这些内容：

* 图片
* CSS 文件
* JavaScript 文件
* 字体文件
* 视频
* 静态 HTML 页面
* 下载文件

例如网站有一张图片：

```text
https://example.com/images/logo.png
```

第一次有用户访问时，CDN 发现自己没有这张图片，就会去网站源站服务器取一次。

流程是：

```text
用户 → CDN 节点 → 源站服务器
```

CDN 拿到图片后，会保存一份。

之后其他用户再访问这张图片时，CDN 就可以直接返回缓存：

```text
用户 → CDN 节点 → 直接返回 logo.png
```

这里的源站服务器，就是网站真正的服务器。

CDN 的好处：

| 作用     | 说明                   |
| ------ | -------------------- |
| 加快访问速度 | 用户从附近节点获取资源          |
| 减轻源站压力 | 很多请求不用打到真正服务器        |
| 提高稳定性  | 某些节点异常时可以切换其他节点      |
| 节省带宽   | 静态资源由 CDN 承担大量访问     |
| 抗高并发   | 热门图片、视频、页面可以由 CDN 分发 |

CDN 和服务器缓存的区别：

| 对比     | CDN 缓存            | 服务器缓存           |
| ------ | ----------------- | --------------- |
| 缓存位置   | CDN 节点，通常分布在各地    | 网站服务器上          |
| 离用户距离  | 更近                | 可能较远            |
| 主要缓存内容 | 图片、CSS、JS、视频、静态页面 | 页面、接口数据、数据库查询结果 |
| 主要作用   | 加速访问、分担流量         | 减少后端计算和数据库查询    |

一句话总结：

> CDN 就是在全国或全球很多地方放了缓存节点，用户访问网站资源时，就近获取，不用每次都访问真正的网站服务器。

---

## 10. 最终总结

缓存的核心思想是：

> 把经常会用到、但不经常变化的内容提前保存起来，下次直接使用。

不同缓存的区别：

| 类型      | 缓存位置          | 主要作用          |
| ------- | ------------- | ------------- |
| 浏览器缓存   | 用户电脑或手机       | 减少重复下载        |
| 服务器缓存   | 网站服务器         | 减少后端计算和数据库查询  |
| CDN 缓存  | 离用户更近的 CDN 节点 | 加快访问速度，减轻源站压力 |
| 数据库查询缓存 | 内存或缓存服务中      | 减少数据库压力       |

可以用一句话理解：

> 浏览器缓存是用户自己存一份，服务器缓存是网站服务器存一份，CDN 缓存是离用户更近的节点存一份。

实际项目中的推荐思路是：

* HTML 页面缓存短一点，或者设置 `no-cache`
* CSS、JS 文件使用文件名 hash，并缓存较长时间
* 图片、字体等稳定资源可以缓存较久
* 内容更新时删除服务器旧缓存
* CDN 缓存更新时主动刷新
* 后端接口或数据库查询结果可以放到 Redis 等缓存中

最终一句话：

> 缓存就是用空间换时间，通过提前保存结果来提高访问速度、减少重复计算、降低服务器和数据库压力。
