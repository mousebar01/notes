在这个项目里，**子 Agent 主要不是做“点击操作”或后台数据处理**，而是做 **主 Agent 的任务委派单元**：当主 Agent 遇到复杂、独立、可拆分、需要专门角色的任务时，通过 `task` 工具把一部分工作交给子 Agent。

可以理解成：

```text
主 Agent：负责和用户聊天、判断任务、拆解任务、汇总最终答案
子 Agent：负责执行某个独立子任务，最后把结果返回给主 Agent
```

## 当前内置子 Agent 大致有这些功能

从代码里看，内置 Agent/子 Agent 主要在 `AgentRepository` 里初始化。这里有几个典型角色。

### 1. `general-purpose`：通用任务子 Agent

这是最基础的子 Agent，名字是“通用任务”，描述是：

```text
面向没有专用角色约束的一般任务，使用默认运行配置独立完成分析、整理、写作或文件处理。
```

它适合被主 Agent 用来处理泛化任务，比如总结文件、整理资料、写一段草稿、分析某个片段。它的 `config_context={}`，也就是没有特殊角色 prompt，更多依赖默认 Agent 能力和主 Agent 给它的 `task.description`。

### 2. `web-search`：网页检索子 Agent

这个子 Agent 专门做网页搜索和资料整理。它的职责是围绕调用方给定的检索目标，持续搜索网页，直到信息足够回答目标。它会拆解问题、多轮调整检索词、交叉验证信息，并要求输出带来源的结构化摘要。

适合场景：

```text
查资料
找最新信息
整理外部网页来源
对多个来源做交叉验证
```

例如主 Agent 可以派给它：

```text
请检索某公司最近三个月的产品更新，返回按时间排序的摘要和来源。
```

### 3. `research-explorer`：调研探索员

这个比 `web-search` 更偏“单个子问题的深度调研”。它的定位是：围绕调用方给定的**单个子问题**，持续检索网页与知识库，直到收集到足够证据。输出要求是结构化发现，不要直接写成完整报告。

适合场景：

```text
把一个大研究问题拆成几个子问题
每个子问题交给一个 research-explorer
最后主 Agent 汇总
```

例如：

```text
请调研“Anthropic 企业产品线的主要变化”，只返回证据和关键发现，不要写完整报告。
```

### 4. `fact-verifier`：事实核查员

这个子 Agent 专门做事实核查。它的 prompt 要求它对论断默认保持怀疑态度，证据不足时倾向判定“存疑”，并逐条给出支持/存疑/反驳、依据来源和置信度。

适合场景：

```text
检查报告里的事实
核验数据和日期
找反例
判断某个结论证据是否充分
```

例如主 Agent 可以派给它：

```text
请核查以下 5 条论断，逐条给出支持/存疑/反驳和证据来源。
```

## 还有一个特殊的 `deep-research`

`deep-research` 严格说不是子 Agent，而是一个**主编排 Agent**。它的定位是“深度研究智能体”，负责整体规划、拆解、调度子 Agent、核验并综合报告。它的配置里明确挂了两个子 Agent：

```python
"subagents": ["research-explorer", "fact-verifier"],
"skills": ["deep-research"]
```

也就是说它自己是主 Agent，但它会优先调用 `research-explorer` 和 `fact-verifier` 来完成调研和核查。

它的工作模式类似：

```text
用户提出研究问题
  ↓
deep-research 拆解子问题
  ↓
research-explorer 分别调研
  ↓
fact-verifier 核查关键结论
  ↓
deep-research 汇总成最终报告
```

## 子 Agent 在系统里的核心作用

它们主要解决这几类问题：

| 功能    | 说明                                                 |
| ----- | -------------------------------------------------- |
| 任务拆分  | 主 Agent 把复杂任务拆成独立子任务                               |
| 专家角色  | 不同子 Agent 有不同 prompt，比如调研、核查、通用处理                  |
| 上下文隔离 | 子 Agent 不直接继承主 Agent 完整聊天历史，只接收 `task.description` |
| 并行处理  | 多个互不依赖的子任务可以并行调用多个 `task`                          |
| 结果回传  | 子 Agent 只把最终结果和 child thread id 返回给主 Agent         |
| 可续跑   | 通过 `thread_id` 可以继续同一个子任务                          |

## 不属于子 Agent 的功能

像你刚才问到的知识图谱提取，就不是子 Agent。它是后台任务 + service + LLM extractor：

```text
图谱构建：MilvusGraphService + LLMGraphExtractor
多 Agent 委派：YuxiSubAgentMiddleware + task 工具 + SubAgentBackend
```

所以，子 Agent 不是用来承载所有自动化动作的。它更适合 **语言型、推理型、研究型、审查型、文件处理型** 的独立任务。

## 一句话总结

这个项目里的子 Agent 主要是给主 Agent 做“专家外包”的：

```text
general-purpose：通用执行
web-search：网页检索
research-explorer：子问题调研
fact-verifier：事实核查
```

而 `deep-research` 是一个会调度这些子 Agent 的主编排 Agent。
