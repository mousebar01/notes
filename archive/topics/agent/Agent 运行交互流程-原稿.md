# Agent 运行交互流程

这篇从用户和前端视角记录一次 Agent Run 的交互闭环，重点是输入、流式过程、来源展示和继续追问，不展开平台内部的扩展架构。

它这个设计的交互逻辑可以概括成：

> 用户用对话发起任务，系统在后台检索知识库/调用工具/执行 Agent，最后把结果以“回答 + 过程 + 来源 + 产物”的形式展示出来。

更具体一点，是下面这条主线。

## 1. 用户先选择能力上下文

用户进入系统后，不是直接面对一个空模型，而是先处在某个工作空间/智能体/知识库上下文里。

常见上下文包括：

```text
当前 Agent
当前知识库
当前模型
当前工具/Skill/MCP
当前会话线程
当前用户权限
```

这些上下文决定了用户这次提问时，系统能访问哪些知识、能调用哪些工具、能用哪个模型。

## 2. 用户通过对话输入需求

用户在聊天框里输入自然语言问题，例如：

```text
帮我总结一下这份制度里差旅报销的规则
```

或者：

```text
根据知识库，告诉我新员工入职流程有哪些步骤
```

前端把这条消息提交给后端，同时创建或复用一个会话线程。

## 3. 后端创建一次 Agent Run

后端不是简单调用一次模型，而是创建一次“运行任务”。

这个运行任务里包含：

```text
用户输入
会话上下文
选中的 Agent
模型配置
知识库配置
工具配置
权限信息
附件信息
```

然后由 Agent 开始执行。

## 4. Agent 判断要不要调用扩展能力

Agent 会根据问题判断是否需要：

```text
直接回答
检索知识库
调用 MCP 工具
执行内置 Tool
调用 Skill
使用子智能体
访问沙箱
生成文件产物
```

如果是知识库问题，一般流程是：

```text
用户问题
  ↓
向量检索 / 关键词检索
  ↓
取回相关文档片段
  ↓
把片段作为上下文交给大模型
  ↓
模型生成带依据的回答
```

如果是工具型任务，则可能是：

```text
用户问题
  ↓
Agent 决定调用工具
  ↓
工具返回结果
  ↓
Agent 继续推理
  ↓
生成最终回答
```

## 5. 前端实时展示执行过程

它不是等所有结果完成后一次性返回，而是通过流式事件逐步展示。

用户会看到类似：

```text
正在思考……
正在调用工具……
正在检索知识库……
正在生成回答……
```

如果有工具调用，会在回答中展示工具调用卡片；如果有推理内容，也可能折叠成“推理过程”。

也就是说，UI 上有两类内容：

```text
最终内容：AI 的回答
过程内容：工具调用、检索、状态、错误、产物生成
```

## 6. 回答完成后展示附加操作

当回答结束后，消息底部会出现操作区：

```text
点赞
点踩
模型名
复制
重新生成
来源
```

如果这次回答使用了知识库或网络搜索，就会显示：

```text
来源 N
```

用户点击后展开来源面板。

## 7. 来源按类型和文件组织

来源不会直接混在正文里，而是作为可展开详情。

比如：

```text
知识库来源 (3)
  员工手册.pdf
    #1 相似度 89%  命中文本预览
    #2 相似度 76%  命中文本预览

网络搜索来源 (2)
  网页标题
  URL
  摘要
```

点击某个知识库片段后，会打开详情弹窗，显示完整 chunk 内容、相似度和来源文件。

## 8. 用户可以继续追问

用户不需要重新配置上下文，可以在同一个会话里继续问：

```text
那试用期员工适用这个规则吗？
```

系统会结合：

```text
上一轮对话
当前 Agent 状态
已选知识库
当前线程文件
```

继续处理。

所以它的交互闭环是：

```text
选择上下文
  ↓
对话输入
  ↓
Agent 执行
  ↓
流式展示
  ↓
返回回答
  ↓
展开来源/查看过程/复制/反馈/重试
  ↓
继续追问
```

一句话总结：

> 这个系统把复杂能力隐藏在对话背后，用户只负责表达目标；Agent 负责判断要调用什么能力；UI 负责把执行过程、最终回答、证据来源和可操作产物分层展示出来。
