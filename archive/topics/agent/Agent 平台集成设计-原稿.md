# Agent 平台集成设计

## 1. 设计定位

本系统采用“对话入口 + 智能体编排 + 扩展能力挂载”的整体设计。用户侧主要通过类 ChatGPT 的对话界面发起请求，系统侧则由智能体负责理解任务、选择模型、调用知识库、使用工具、执行扩展能力，并最终将结果以自然语言或结构化产物的形式返回给用户。

这种设计的核心目标是：降低用户使用门槛，同时保留系统在复杂任务处理、企业知识接入、外部工具集成和自动化执行方面的扩展能力。

## 2. 核心交互模式

系统以对话作为统一入口。用户不需要理解底层有哪些工具、服务或流程，只需要用自然语言描述目标，例如查询资料、总结文档、分析问题、生成报告或执行某个业务任务。

对话请求进入系统后，会被交给智能体处理。智能体根据当前上下文、用户意图、权限范围和可用能力，决定是否需要调用大模型、检索知识库、访问外部服务、执行工具、调用 MCP 服务或委派给子智能体完成。

整体流程可以概括为：

```text
用户对话输入
  ↓
智能体理解任务
  ↓
选择模型与上下文
  ↓
调用知识库 / 工具 / Skills / MCP / 子智能体
  ↓
整合结果
  ↓
返回回答或产物
```

## 3. 智能体作为运行核心

系统中的智能体不是简单的模型调用封装，而是任务执行的核心调度单元。它负责连接用户意图与系统能力，并在执行过程中维护上下文、状态和中间结果。

智能体可以具备以下能力：

- 调用指定的大语言模型进行理解、推理和生成
- 访问企业知识库并进行 RAG 检索
- 使用知识图谱进行关系查询和辅助推理
- 调用工具完成搜索、文件处理、代码执行等任务
- 挂载 Skills 实现特定领域或流程能力
- 调用 MCP Server 接入外部系统
- 委派子智能体处理复杂任务的子步骤
- 使用沙箱环境生成、处理或验证文件与代码

因此，智能体层承担的是“编排”和“执行”的角色，而不仅仅是“聊天回复”的角色。

## 4. 扩展能力设计

系统将不同类型的能力以可挂载、可配置、可组合的方式接入智能体。这样可以避免把所有功能硬编码到主流程中，也便于后续扩展和维护。

主要扩展能力包括：

| 类型 | 作用 |
| --- | --- |
| 知识库 | 接入企业文档、资料、制度、产品说明等内容，用于检索增强生成 |
| 知识图谱 | 表达实体关系，支持复杂关联查询和推理 |
| 工具 | 提供搜索、计算、文件处理、代码执行等基础操作能力 |
| Skills | 封装特定任务流程、提示词、工具组合和领域能力 |
| MCP | 接入外部系统或第三方服务，将其能力暴露给智能体调用 |
| 子智能体 | 将复杂任务拆分给多个专门角色处理 |
| 沙箱 | 提供隔离执行环境，用于代码运行、文件生成和任务验证 |

这种扩展机制使系统具备类似插件化的能力。新增业务功能时，可以优先考虑以 Skill、Tool 或 MCP 的形式接入，而不是修改核心对话流程。

## 5. 与 MCP 的关系

MCP 是系统扩展能力的一种重要形式，但不是唯一形式。

MCP 更适合用于连接外部系统，例如数据库、代码仓库、企业内部服务、第三方 API 或业务平台。通过 MCP，外部系统可以以标准化协议向智能体暴露工具能力。

而系统内建的 Skills、Tools、知识库和子智能体机制，则更偏向平台内部能力组织。它们可以与 MCP 共同使用，形成更完整的智能体能力体系。

因此，可以将 MCP 理解为“外部能力接入协议”，而 Skills 和 Tools 更像是“平台内部能力封装方式”。

## 6. 设计优势

该设计具备以下优势：

1. **用户入口简单**
   用户只需要通过对话表达需求，不需要理解复杂的功能菜单或流程配置。

2. **能力扩展灵活**
   新能力可以通过知识库、工具、Skills、MCP 或子智能体接入，减少对核心系统的侵入。

3. **适合企业知识场景**
   系统可以将企业内部文档、知识库、知识图谱和业务系统接入智能体，使回答更贴近企业实际数据。

4. **支持复杂任务执行**
   智能体可以在一次对话中完成检索、分析、调用工具、生成文件、验证结果等多步骤任务。

5. **便于权限和多租户管理**
   在企业场景下，可以根据用户、租户、角色或部门控制可访问的知识库、工具和智能体能力。

6. **便于后续生态化**
   通过 Skills、MCP 和工具机制，可以逐步沉淀可复用的能力组件，形成平台扩展生态。

## 7. 总结

整体来看，该系统不是单一的聊天机器人，而是一个以对话为入口的智能体平台。对话界面负责降低使用门槛，智能体负责理解和编排任务，知识库、工具、Skills、MCP、子智能体和沙箱负责提供可扩展的执行能力。

其设计思想可以概括为：

> 用对话统一用户入口，用智能体承接任务执行，用插件化扩展机制连接知识、工具和外部系统。
