# 非破坏式数据流设计（Non-Destructive Workflow）

这篇笔记由 Blender 修改器的学习延伸而来，记录一种不直接覆盖源数据、而是通过规则和处理步骤生成结果的通用设计思想。

这个概念不只是 Blender 的知识，也是一种**通用的软件架构思想**。以下按“设计文档”的方式整理。

## 一句话定义

> **非破坏式设计指：不直接修改原始数据，而是通过一系列可撤销、可调整的处理步骤生成最终结果。**

核心思想：

> **保留源数据，让变化成为一层“规则”或“计算过程”。**

---

## 1. 传统破坏式流程（Destructive）

传统方式：

```
原始数据
    |
    ↓
直接修改
    |
    ↓
新数据
```

例如：

一个球：

```
Sphere
 ↓
细分
 ↓
修改顶点
 ↓
雕刻
```

修改后：

* 原来的球不存在了
* 很难回退
* 修改成本越来越高

类似：

Photoshop：

```
图片
 ↓
直接涂黑
 ↓
保存
```

之后：

“我想恢复原来的部分？”

很麻烦。

---

## 2. 非破坏式流程

非破坏式：

```
原始数据
    |
    |
    ↓
Modifier / Transform / Rules
    |
    ↓
Evaluation（计算结果）
    |
    ↓
最终显示
```

例如 Blender：

```
Mesh
 |
 ├── Mirror Modifier
 |
 ├── Subdivision Modifier
 |
 ├── Bevel Modifier
 |
 └── Material
        |
        ↓
     Render Result
```

注意：

Mesh 本身没有被修改。

修改器只是：

> “告诉系统如何生成结果。”

---

## 3. Blender 中三个重要层级

## Layer 1：原始数据（Source）

真正保存的数据：

例如：

```
Mesh:
- Vertex
- Edge
- Face
```

这是“事实”。

---

## Layer 2：规则（Operations）

例如：

```
Mirror
Subdivision
Boolean
Array
```

这些不是模型。

它们是：

```
函数 / 算法
```

例如：

数学上：

```
Result = Mesh + Modifier(Mesh)
```

---

## Layer 3：评估结果（Evaluated Result）

用户看到的：

```
最终形状
```

它是计算出来的。

所以：

你看到一个圆滑球：

不代表：

```
Mesh = 高模球
```

可能只是：

```
低模球 + Subdivision
```

---

## 4. 为什么需要非破坏式？

因为它提供：

## ① 可逆性（Reversibility）

例如：

细分：

```
Level 2
```

不好看：

改：

```
Level 1
```

不用重新建模。

---

## ② 参数化（Parametric）

变化不是结果，而是参数。

例如：

倒角：

不是：

```
修改边
```

而是：

```
Bevel Width = 0.02
```

未来：

```
0.02 → 0.05
```

整个模型更新。

---

## ③ 组合能力（Composability）

多个规则可以叠加：

例如：

```
Mesh
 ↓
Mirror
 ↓
Subdivision
 ↓
Bevel
 ↓
Material
```

像软件管线：

```
Input
 ↓
Transform
 ↓
Filter
 ↓
Output
```

---

## 5. “应用修改器”是什么意思？

应用（Apply）：

就是：

> 把动态规则计算出来的结果，写回原始数据。

之前：

```
Mesh
 +
Subdivision
 =
Result
```

应用：

```
Result → Mesh
```

之后：

```
Mesh（已经变成高模）
```

修改器消失。

---

## 6. 非破坏式和软件工程的对应关系

这个非常像：

## 函数式思想

不要：

```
修改变量 A
```

而是：

```
newState = transform(A)
```

---

## 数据流水线

类似：

```
Raw Data
   |
   ↓
Processing Pipeline
   |
   ↓
Output
```

例如：

编译器：

```
Source Code
 ↓
Lexer
 ↓
Parser
 ↓
AST
 ↓
Machine Code
```

不会直接把源代码改成机器码。

---

## React 状态管理

类似：

```
State
 +
Components
 +
Rules
 ↓
UI
```

UI 是结果，不是数据本身。

---

## 7. 非破坏式设计的代价

它不是没有缺点。

成本：

## ① 增加抽象

用户需要理解：

```
看到的 ≠ 存储的
```

---

## ② 调试复杂

出现问题时：

要问：

```
是原始数据错？
还是某个处理步骤错？
```

---

## ③ 性能成本

实时计算多个 Modifier。

---

## 8. Blender 学习中的核心心智模型

不要问：

> “这个按钮会改变什么？”

改成：

> “这个操作是在修改数据，还是添加一个计算规则？”

例如：

| 操作   | 本质           |
| ---- | ------------ |
| 移动物体 | 改变 Transform |
| 编辑顶点 | 改变 Mesh      |
| 添加细分 | 增加规则         |
| 应用细分 | 固化结果         |
| 材质节点 | 定义表面计算       |
| 渲染   | 执行最终计算       |

---

## 最终总结

> **非破坏式数据流是一种把“变化”从数据本身分离出来的设计方式。原始数据保持稳定，所有修改以规则、参数和计算流程存在。这样系统获得可逆性、可组合性和可维护性。**

---

如果你以后做软件架构，这个思想其实会反复出现：

* Photoshop 图层
* CAD 参数化建模
* Blender 修改器
* Unreal 材质节点
* React 声明式 UI
* 数据处理 Pipeline

本质都是同一个思想：

> **不要急着改变结果，先描述生成结果的方法。**

这句话很适合放在你的 Blender 笔记第一页。🙂
