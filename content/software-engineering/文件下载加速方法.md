# 文件下载加速方法

这篇笔记记录大文件下载时的瓶颈判断、常用加速方式和工具选择，重点是合法资源的多连接下载与断点续传。

## 先判断瓶颈

下载速度不只取决于下载器，还可能受以下因素限制：

- 下载源距离远或服务器总带宽不足；
- 服务端限制单连接速度；
- 本地网络不稳定或已被其他任务占满；
- 网盘、包管理器等平台自身限速；
- 资源不支持 HTTP Range 或没有足够的 P2P 节点。

如果瓶颈是单连接限速，多连接分段通常有效；如果服务端限制总速率，增加线程数也不会更快。

## 下载方式与适用场景

| 方式 | 常用工具 | 适用场景 |
| --- | --- | --- |
| HTTP / HTTPS 直链 | 浏览器、`curl`、`wget`、aria2 | 普通文件和大模型权重 |
| FTP / SFTP | FileZilla、WinSCP、`curl` | 服务器、镜像站和内部文件 |
| 包管理器 | apt、pip、npm、conda、Docker | 软件、依赖和镜像 |
| BT / P2P | qBittorrent、Transmission、aria2 | 有足够节点的大文件分发 |
| 网盘 | 官方客户端 | 受平台权限和限速策略管理的文件 |

优先选择离自己更近的官方镜像或 CDN 节点。对开发依赖，切换可信镜像通常比更换下载器更直接。

## 为什么 aria2 可能比 curl 快

`curl` 下载单个文件时通常使用一条顺序连接。aria2 可以利用 HTTP Range 把文件拆成多个区间，并发建立连接，最后在本地合并；它也支持中断后继续下载。

```bash
aria2c -x 8 -s 8 -c "https://example.com/large-file"
```

- `-x 8`：对单个服务器最多使用 8 条连接；
- `-s 8`：把文件拆为 8 个分片；
- `-c`：继续未完成的下载。

下载 10 GB、20 GB 这类文件时，可以从 8 条连接开始；网络和服务端允许时再尝试 16 条。连接数过高可能触发限流、增加失败率，也会给服务端带来额外压力。

## 推荐组合

- 普通小文件：浏览器或 `curl` / `wget`；
- HTTP 大文件：aria2 或 Motrix，多连接并启用断点续传；
- 开源软件与开发依赖：官方镜像或可信的地区镜像；
- 热门种子资源：qBittorrent 或 aria2；
- 网盘文件：使用官方客户端和平台提供的加速能力。

改善有线网络、关闭占带宽任务或避开高峰期，有时比提高并发数更有效。

加速只应用于有权下载的资源，不应绕过平台限制、破解会员能力或运行来源不明的脚本。
