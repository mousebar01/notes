# 线程 I/O、异步 I/O 与协程

这是一条关于并发模型的初步理解。原始记录里还有不准确或尚未确认的地方，因此同时保留原文和整理版，方便以后继续修正。

## 原始记录

> 线程是通过阻塞主线程实现的。
>
> 异步 I/O 是少量线程实现大量等待事件。尽量不阻塞线程，而是通过事件通知实现，这里是通过事件循环完成的。
>
> 并发规模大的时候要考虑用异步 I/O。
>
> 协程是可以挂起、可以恢复的函数或者任务。
>
> 异步 I/O 的运行过程：先发起异步 I/O 请求 -> 等待注册 I/O -> 当前任务挂起 -> 执行 -> 等待任务执行完再通知 -> 继续之前的任务 -> 有结果后返回结果 -> 执行计算 -> 完成并回到之前的任务？

## 整理版

- **线程阻塞 I/O**：发起 I/O 的线程会在等待结果时阻塞，但被阻塞的不一定是主线程，也可以是工作线程。扩大并发通常需要增加线程数量。
- **异步 I/O**：任务发起 I/O 后让出执行权，由事件循环或运行时等待完成通知，因此少量线程可以管理大量以等待为主的任务。
- **协程**：一种可以挂起和恢复的任务抽象。它让异步流程可以按接近同步代码的方式表达，但协程本身不等于异步 I/O。
- **适用判断**：连接数多、等待时间长、单次计算较少的 I/O 密集场景，更适合考虑异步 I/O；CPU 密集任务仍需要线程或进程等并行手段。

## 待继续确认
