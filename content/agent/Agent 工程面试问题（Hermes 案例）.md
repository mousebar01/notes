# Agent 工程面试问题：Hermes 案例

这篇把 Hermes 阅读中遇到的通用工程概念整理成短问答。具体实现可能随版本变化，回答重点是职责边界；Hermes 细节以 [工程模式主文档](./Hermes%20Agent%20工程模式提炼.md) 为准。

## MCP 解决什么问题

MCP 用统一协议让 Agent 发现并调用外部工具、资源或提示模板。它规范的是能力接入，不负责 Agent 自身的规划、权限模型和任务恢复。

## ACP 和 MCP 有什么区别

MCP 更像“Agent 调用外部能力”；ACP 更像“编辑器或客户端调用一个 Agent”。前者暴露工具面，后者暴露 Agent 会话与执行入口。

## JSON-RPC 适合什么场景

JSON-RPC 适合为跨进程或跨语言调用定义方法、参数、结果和错误。它轻量、易调试，但传输、安全、流式和状态恢复仍需协议外约定。

## Gateway / Adapter 模式解决什么问题

不同聊天平台、编辑器和 API 的事件格式不同。Adapter 把外部差异转换为统一的 session、message 和 tool schema，使核心 Agent loop 不必理解每个平台。

## 为什么并发会话需要 `contextvars`

当前用户、thread、cwd 和审批上下文不能放在进程全局变量里，否则并发请求会串状态。`contextvars` 让上下文随异步调用链传播；进入线程池时还要显式复制上下文。

## SQLite WAL 为什么适合本地 Agent 状态

WAL 允许读写更好地并发，并保留 SQLite 单文件、低运维的优势，适合本地 session、任务和事件日志。它不等于分布式数据库，多主写入和跨机器协调仍是边界。

## OAuth 2.1 / PKCE 在 MCP 中的作用

当 MCP server 代表用户访问外部资源时，需要安全授权而不是共享长期密码。PKCE 绑定授权请求与 token 交换，降低授权码被截获后直接使用的风险。

## Provider 与 Transport 为什么要分层

Provider 表达模型能力、认证和请求语义；Transport 表达 HTTP、WebSocket、stdio 等通信方式。分层后，同一模型能力可以切换传输实现，协议细节也不会污染业务接口。

## Tool Schema 为什么应动态生成

工具注册不等于当前可用。模型看到的 schema 应根据用户权限、运行模式、依赖、凭证和会话配置生成最小能力面，避免描述无法执行或不应执行的工具。

## Agent 审批系统怎么设计

审批应建立在分层风险模型上：不可恢复操作始终拦截，高风险命令按策略请求确认，普通操作尽量减少打扰。即使是高信任模式，也不应取消 hardline block、参数校验和审计记录。

## Foreground 与 Background Process 为什么要分开

前台命令与当前交互绑定，用户可以观察和中止；后台进程生命周期更长，需要 registry、状态查询、日志、超时和清理。把二者混在一次 shell 调用里会失去恢复和审计能力。

## Session、Memory 与 Search 的区别

- Session 保存当前会话事件和状态。
- Memory 保存经过筛选的长期事实与偏好。
- Search 按需查找过去消息、文件和任务细节。

把全部历史写进 Memory 会增加 prompt 成本，并把临时事实误当成长期事实。

## 上下文压缩为什么要保护工具调用配对

压缩点如果落在 tool call 与 tool result 之间，模型会看到不完整因果链。实现需要选择合法边界，保留近期消息，并把旧历史迁移为能继续工作的结构化摘要。

## 多 Agent 为什么区分同步委派与持久任务

同步子任务依附当前 turn，适合临时 fan-out 和汇总；持久任务跨 turn、跨进程，需要状态机、租约、重试和人工介入。两者生命周期不同，不应只用一个“subagent”概念覆盖。

## 配置与 Secret 为什么要分开

配置适合版本化和共享，Secret 需要最小暴露、独立存储和轮换。将 token 写进普通配置会扩大日志、提交记录和插件读取造成的泄漏面。

## Observability 为什么默认本地

Agent trace 可能包含 prompt、文件、命令输出和凭证。默认本地记录并做脱敏，外部上传显式 opt-in，可以在排障价值和隐私风险之间保持清楚边界。

## 总体判断

这些问题背后是同一个设计原则：

```text
状态存储 != 上下文窗口
工具注册 != 工具暴露
长期记忆 != 历史搜索
同步委派 != 持久任务
高信任模式 != 取消安全底线
外部入口 != 核心 Agent loop
```

Agent 工程的核心不是继续增加模型能力，而是让状态、工具、权限、上下文和任务生命周期可恢复、可审计、可组合。
