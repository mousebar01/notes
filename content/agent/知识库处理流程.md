# 知识库处理流程

这篇笔记从产品与工程视角概览 RAG 知识库从数据接入、索引构建到检索、回答和持续评估的完整流程，不展开具体框架实现。

对，你抓到主线了。知识库功能通常可以拆成一条完整流水线：

```text
创建知识库
  ↓
上传/接入数据
  ↓
解析
  ↓
清洗
  ↓
切分
  ↓
向量化
  ↓
入库
  ↓
检索
  ↓
重排
  ↓
组装上下文
  ↓
生成回答
  ↓
展示来源
```

如果按产品功能来分，可以分成这几大块。

## 1. 知识库管理

这是最外层的管理功能。

包括：

```text
新建知识库
选择知识库类型
设置名称/描述
配置权限
删除/归档知识库
查看知识库状态
```

比如你截图里看到的：

```text
Yuxi
Dify
Notion
```

就是在选择知识库的后端类型。

## 2. 数据接入

也就是你说的“上传”。

来源可以有几类：

```text
上传文件
上传文件夹
解析 URL
连接工作区
连接第三方知识库
```

文件类型包括：

```text
PDF
Word
PPT
Excel
Markdown
TXT
HTML
图片
CSV
JSON
ZIP
```

外部来源则可能是：

```text
Dify Dataset
Notion
网页 URL
企业网盘
内部文档系统
```

## 3. 文档解析

上传后不能直接检索，需要先把文件内容抽出来。

不同文件有不同解析方式：

```text
PDF → 提取文字 / OCR / 版面分析
Word → 提取正文、标题、表格
PPT → 提取每页文本
Excel → 提取表格内容
图片 → OCR 识别
HTML/URL → 提取正文
ZIP → 解压后逐个解析
```

你截图里看到的：

```text
OCR 引擎（仅应用于 PDF/图片文件）
```

就是解析阶段的配置。

## 4. 内容处理

解析出来的内容通常还不能直接用，需要处理。

包括：

```text
去除空白和乱码
保留标题层级
处理表格
处理图片 OCR 结果
过滤无效内容
统一编码
补充元数据
```

元数据很重要，比如：

```text
文件名
页码
章节
段落位置
上传人
更新时间
知识库 ID
chunk_id
```

这些后面会用于来源展示。

## 5. 分块 Chunking

大模型不能一次塞完整文档，所以要切成小片段。

常见策略：

```text
按段落切
按标题切
按 token 长度切
按表格/页面切
滑动窗口重叠
语义分块
```

分块结果类似：

```json
{
  "chunk_id": "xxx",
  "content": "员工应在费用发生后30天内提交报销申请……",
  "metadata": {
    "file_name": "报销制度.pdf",
    "page": 12,
    "section": "第三章 报销时限"
  }
}
```

## 6. 向量化 Embedding

每个 chunk 会调用 embedding 模型转成向量。

```text
文本片段 → embedding 模型 → 向量
```

然后存入向量数据库，比如 Yuxi 用的是 Milvus。

作用是：用户问问题时，可以通过语义相似度找到相关片段。

## 7. 入库与索引

向量、原文片段、元数据会一起保存。

通常包括：

```text
向量数据库：Milvus
文件存储：MinIO / 本地 volume
结构化数据库：PostgreSQL
缓存/任务队列：Redis
```

入库完成后，知识库才真正可用。

## 8. 检索

用户提问时，系统会把问题也转成向量，然后去知识库里找相似 chunk。

```text
用户问题
  ↓
问题向量化
  ↓
Milvus 相似度检索
  ↓
返回 top-k 文档片段
```

也可以结合关键词检索、过滤条件、权限过滤等。

## 9. 重排 Rerank

第一次检索可能只看向量相似度，不一定最准确。

所以可以再用 reranker 模型重新排序：

```text
候选 chunk 20 个
  ↓
reranker 判断与问题相关度
  ↓
保留最相关的 5 个
```

这一步能明显提升回答质量。

## 10. 上下文组装

系统把检索到的 chunk 组装成 prompt 上下文：

```text
用户问题
相关知识片段
引用信息
回答要求
```

然后交给大模型生成最终回答。

## 11. 回答与来源展示

最后 UI 展示：

```text
AI 回答
来源按钮
知识库来源列表
命中片段
相似度
文件名
chunk 详情
```

也就是你前面问到的“知识库结果怎么呈现”。

## 12. 维护与评估

成熟知识库还会有维护功能：

```text
重新解析
重新入库
删除文件
查看失败原因
查看 chunk
检索测试
RAG 评估
命中率评估
问答效果评估
```

你截图顶部有：

```text
知识图谱
RAG 评估
评估基准
```

这些就属于知识库增强和质量评估能力。

可以把它总结成三大阶段：

```text
一、构建阶段：上传 → 解析 → 处理 → 分块 → 向量化 → 入库

二、使用阶段：提问 → 检索 → 重排 → 生成 → 引用展示

三、维护阶段：更新 → 重建索引 → 测试检索 → 评估效果
```

你说的“上传 → 解析 → 处理”是构建阶段的前半段，后面还会接 **分块、向量化、入库、检索、重排、生成**。
