# Agent 安全与沙箱

这篇是 Agent 安全相关笔记的专题入口。当前重点不在“模型是否永远不会被诱导”，而在于：当模型被诱导产生危险意图以后，系统的工具边界、权限边界、不可信内容边界和沙箱边界能不能兜住。

## 当前已有笔记

- [Agent 提示词攻击测试流程](./Agent%20提示词攻击测试流程.md)
  - 收敛后的主文档，包含执行顺序、分层断言、测试矩阵和攻击载荷样例。
  - 核心观点：Agent 安全测试不能只看模型拒绝，还要验证工具调度层和执行环境是否能拦住危险动作。

- [AstrBot Agent 沙箱调研](./AstrBot-Agent-沙箱调研.md)
  - 记录 AstrBot Agent 沙箱的能力、driver / profile、权限控制和资源限制。
  - 核心观点：沙箱不是简单的代码执行器，而是 Agent 工具调用和文件操作的隔离执行边界。

- [零信任与 Agent 时代安全](./零信任与%20Agent%20时代安全.md)
  - 零信任概念（NIST 800-207）、去中心化与信任模型、agent 时代需要零信任的环节（工具权限、凭据、网络出口、审批门等）和提示注入威胁。
  - 核心观点：传统零信任是“对人验证”，agent 时代是对“每一次工具调用验证”。

## 当前判断

安全测试可以直接假设模型已经被诱导成功，然后检查工具调度层和执行环境是否仍能拒绝越权动作。模型拒绝不是最终防线。
