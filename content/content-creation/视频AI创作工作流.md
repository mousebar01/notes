# 视频 AI 创作工作流：OpenMontage 项目观察

这篇笔记保留对 OpenMontage 一类 AI 影视创作项目的结构观察：项目如何把创作经验写成知识文件，再由通用编码 Agent 组合工具、素材和审核流程完成交付。

> [!NOTE]
> 这是一份项目阅读笔记，不是完整的工具实测报告。原始仓库地址和分析版本尚未记录，文中的目录及文件路径以当时分析对象为准，来源待补充。

## 三个核心判断

1. **创作知识可以成为运行时的一部分。** 导演经验、提示词策略和审核标准不必全部写死在代码里，也可以由 Agent 直接读取 Markdown 和 YAML。
2. **不同视频类型需要不同流程。** 电影短片、解释动画、口播、播客二创和批量短视频不能共用一套固定生成链路。
3. **生成只是中间步骤。** 策划、素材选择、剪辑、混音、成本控制和质量审核共同决定最终结果。

## 知识与执行结构

项目把知识大致分成三层：

| 层级 | 解决的问题 | 项目位置 |
| --- | --- | --- |
| 能力层 | 有哪些工具可以调用 | `tools/`、`pipeline_defs/` |
| 创作方法层 | 工具应该怎样用于视频创作 | `skills/` |
| 技术知识层 | FFmpeg、Remotion、模型 API 等如何工作 | `.agents/skills/` |

值得注意的是，项目运行时没有把所有步骤固化为一个 LLM 编排程序。Claude Code、Codex、Cursor 等 Agent 可以读取流程定义和创作规范，再调用 Python 工具执行。这种结构把“怎么判断”与“怎么调用”分开，也让创作方法能够独立修改。

## 从需求到成片

项目中的完整链路可以概括为：

```text
创意与需求理解
→ 研究或参考片分析
→ 脚本创作
→ 场景与镜头规划
→ 素材生成或搜索
→ 剪辑与画面合成
→ 发布包装
→ 自动质量审核
```

不同内容类型使用不同 Pipeline，例如：

- `cinematic.yaml`：电影感短片
- `animation.yaml`：动画解释视频
- `documentary-montage.yaml`：纪录片蒙太奇
- `avatar-spokesperson.yaml`：数字人讲解
- `podcast-repurpose.yaml`：播客二创
- `talking-head.yaml`：口播视频
- `screen-demo.yaml`：屏幕演示
- `clip-factory.yaml`：批量短视频

流程、节奏、素材来源和质量标准随视频类型变化，而不是先选定一种模型，再让所有任务迁就它。

## 观察一：先结构化创意需求

`skills/meta/creative-intake.md` 和 `video-reference-analyst.md` 会关注目标、观众、平台、时长、画幅、风格、核心信息、参考视频、预算和禁用内容。

这里有两个有用的处理原则：

- 需求模糊时，Agent 应形成明确且可被确认的创意假设，而不是把访谈变成机械问卷。
- 需求已经具体时，不重复询问；直接把约束转成脚本、镜头和交付条件。

参考视频分析也不止是概括主题，还会拆解镜头长度、节奏、构图、字幕、转场、音乐节拍、视觉密度、色彩和叙事结构，并区分可以借鉴的模式与不应复制的内容。

## 观察二：叙事方法被写成可执行规则

`skills/creative/storytelling.md` 和各 Pipeline 的 `script-director.md` 把解释视频拆成钩子、信息缺口、基础概念、复杂性、核心洞察、案例、现实意义和回扣开头。

原稿中特别值得保留的三种方法是：

- **But–Therefore**：用“但是”制造冲突，用“因此”推进因果，避免脚本退化为知识点列表。
- **误解优先**：先展示一个看似合理的错误认知，再说明它在哪里失效。
- **引导式发现**：提出问题，让直觉解法失败，再逐步构建关键洞察。

项目还要求把“史诗感、治愈、激励”等主观词翻译成镜头、光线、动作、空间和声音变化。例如，与其写“音乐高潮”，不如写“先静音 1.5 秒，再以半速低频鼓点进入”。这样生成模型拿到的是可执行条件，而不是情绪标签。

## 观察三：提示词描述时间与空间

`skills/creative/video-gen-prompting.md` 和 `lib/shot_prompt_builder.py` 将视频提示词组织为五部分：

```text
主体 + 主体动作 + 环境场景 + 空间关系 + 摄影机
```

其中最容易遗漏的是动作、空间关系和摄影机运动。多个动作按时间顺序描述；没有时间关系时，按主体重要程度组织。

项目没有把同一套长提示词交给所有模型，而是按模型特性调整密度：LTX、Runway 偏短且重动作，Veo、Sora 使用中等长度，Seedance、Wan 可以接受更长的结构化描述。失败时先删减和定位变量，而不是继续堆叠风格词。

## 观察四：跨镜头一致性需要单独设计

`skills/creative/image-gen-usage.md`、`styles/*.yaml` 和提示词构建工具共同维护调色板、材质、线条、光线、镜头语言、构图和运动能量。

项目使用三类锚点：

- 先生成一张高质量 Hero Reference，作为角色或风格基准。
- 支持时复用 Seed，得到更可控的变体。
- 每个镜头同时包含当前场景要求、简短风格锚点和具体人物动作。

探索阶段可以使用低成本模型出故事板，关键镜头再用中高质量模型重绘。标题、字幕和标签则交给 Remotion、HyperFrames 或其他合成工具处理，不依赖图像模型生成准确文字。

## 观察五：素材来源由信息任务决定

`skills/creative/broll-planning.md` 和 `stock-sourcing-usage.md` 没有默认“一切都由 AI 生成”。真实城市、人物、设备、档案和自然运动更适合图库或实拍；抽象概念、不存在的世界、品牌插画和定制隐喻更适合生成。

每段脚本会被转成结构化素材需求：

```text
场景编号、时间范围、画面任务、素材来源、搜索词、
时长、画幅、风格以及失败后的备用方案
```

图库搜索使用短关键词，并优先确认视角。颜色常能在后期调整，但把手持素材当成无人机镜头通常无法通过裁剪补救。

## 观察六：声音和剪辑仍需要后期判断

项目中的声音链路包含 TTS、AI 音乐、音效、音频增强、混音和音量标准化。音乐提示词会描述类型、BPM、调性、乐器、结构、是否有人声及它在视频中的功能，而不是只写“激励人心”。

AI 配音也被当作原始素材，需要按情况去噪、EQ、压缩、去齿音、修正停顿和处理背景音乐 Ducking。

剪辑规范关注语义而不是固定秒数：哪些自然停顿应该保留，B-roll 何时覆盖口播，生成片段首尾的不稳定区域如何处理。主体变化还被区分为出现、消失、焦点切换和复杂交替，帮助 Agent 明确注意力如何移动。

## 观察七：精确视觉优先使用程序化工具

项目根据内容选择不同渲染方式：

| 内容 | 更适合的方式 |
| --- | --- |
| 数学和几何推导 | Manim |
| 字幕、信息卡、时间轴 | Remotion |
| 动态网页、产品宣传和动效排版 | HyperFrames / GSAP |
| 风格化场景 | AI 图像或视频 |
| 结构关系 | Diagram 工具 |
| 数据变化 | 程序化图表 |

开放式视觉适合生成模型；需要文字准确、数学准确、品牌一致和精确时间控制的部分，更适合代码动画。

## 观察八：模型选择与预算共同进入流程

`video_selector.py`、`image_selector.py`、`tts_selector.py` 和 `lib/scoring.py` 会综合可用性、API Key、质量、速度、成本、任务匹配度、本地或云端以及预算限制选择供应商。

`tools/cost_tracker.py` 则在生成前估算、调用后记录费用，并区分探索稿与最终稿的质量等级。这个设计尤其适合批量内容，因为失败重试和素材变体会迅速放大成本。

## 观察九：交付前分阶段审核

`skills/meta/reviewer.md` 及 `tools/analysis/` 下的工具把审核分成三层：

1. 脚本和方案是否符合目标，是否存在模板化、事实或逻辑问题。
2. 场景是否服务脚本，镜头、构图和视觉推进是否足够。
3. 合成结果是否存在画幅、字幕安全区、音画同步、峰值、黑帧或缺失素材问题。

项目还专门检查 Slideshow Risk：静态素材过多、只有简单缩放、场景缺少变化、信息卡过密，以及画面与旁白没有联动。这个检查提醒我们，渲染成功不等于视频成立。

| 文件 | 重点 |
| --- | --- |
| `index.md` | 项目定位和完整链路 |
| `docs/ARCHITECTURE.md` | Agent 编排、知识分层和质量治理 |
| `skills/creative/storytelling.md` | 叙事与注意力设计 |
| `skills/creative/video-gen-prompting.md` | 视频提示词结构 |

| `skills/meta/reviewer.md` | 交付审核 |
| `pipeline_defs/*.yaml` | 不同视频类型的流程组合 |
| `lib/shot_prompt_builder.py`、`lib/scoring.py` | 创作知识如何落实为程序逻辑 |

这套项目最值得借鉴的不是某个 Prompt，而是把创意结构化、模型选择、素材生产、程序化合成、成本和审核放进同一条可追踪的工作流。

图文媒介中真正不同的选题、文案、素材、排版和分发判断，另见 [图文创作方法论](./图文创作方法论.md)。
