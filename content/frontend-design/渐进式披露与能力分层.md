# 渐进式披露与能力分层

这篇笔记讨论如何让常见任务保持简单，同时为进阶用户保留更深的控制能力。

可以把这个设计原则总结成一句话：

> **让用户用最少的认知成本完成常见任务，同时保留深入控制的能力。**

它背后包含几个核心原则：

---

## 1. 默认简单（Simple by Default）

**用户第一次使用时，不应该面对全部复杂性。**

好的设计：

```
新手
 ↓
立即完成简单任务
```

而不是：

```
新手
 ↓
学习整个系统
 ↓
终于能开始
```

例子：

好的：

* 手机拍照 → 按快门

不好的：

* 拍照前先设置曝光曲线、色彩空间、镜头参数

---

## 2. 渐进式披露（Progressive Disclosure）

> 复杂功能存在，但不要一开始全部展示。

结构：

```
80%的用户
    ↓
常用功能

20%的用户
    ↓
高级功能

专家
    ↓
底层控制
```

例如 Photoshop：

普通用户：

* 裁剪
* 调色

设计师：

* 图层
* 蒙版

专家：

* 通道
* 色彩管理

---

## 3. 不为不用的东西付出成本（Pay Only For What You Use）

这个和 C++ 的思想很接近：

> 不使用的能力，不应该增加负担。

负担包括：

### 软件：

* 更多按钮
* 更多概念
* 更多学习成本

### 程序：

* 更多运行开销
* 更多复杂度

理想状态：

简单任务保持简单。

复杂任务才引入复杂性。

---

## 4. 能力分层，而不是能力隐藏

一个误区：

> 简单 = 删除高级功能

其实不是。

好的系统：

```
简单入口
    |
    |
高级入口
    |
    |
底层控制
```

例如 Blender：

新手：

> 加球 → 调大小

进阶：

> 修改器 → 细分

专家：

> 手动控制拓扑、法线、UV

---

## 5. 降低认知负担（Reduce Cognitive Load）

人的注意力有限。

优秀设计会减少：

* 记忆
* 推理
* 决策

增加：

* 直觉
* 反馈
* 可发现性

例如：

按钮显示：

“撤销”

比：

“回滚最近一次状态变更事务”

更符合人的思维。

---

## 6. 给专家留下逃生通道（Power Without Forcing Complexity）

专业工具的关键：

> 新手不用懂全部，但专家可以控制全部。

例如：

汽车：

普通驾驶：

* 油门
* 刹车

赛车：

* 手动挡
* 悬挂调节
* 动力分配

不能因为普通人不会调悬挂，就取消悬挂。

---

## 一个完整总结模型：

```
          专家控制
             ↑
             |
        高级能力
             ↑
             |
        常用功能
             ↑
             |
        简单入口
```

好的设计：

✅ 下层能力存在
✅ 上层体验简单
✅ 用户可以逐渐深入

坏的设计：

❌ 一开始暴露所有复杂性
❌ 强迫所有人学习底层逻辑
❌ 简单任务也需要专业知识

---

如果用一句更像工程师的话总结：

> **好的系统应该提供低门槛的默认路径，同时保持高上限的扩展能力；复杂性应该被延迟暴露，而不是提前转嫁给用户。**

这也是为什么很多现代工具都在往“自然语言 + AI 助手”方向走：AI 的价值之一，就是把过去必须学习的复杂操作层，变成可调用的能力层。你刚才提 Blender + MCP，其实正是在探索这种“新的交互层”。
