# AI Coding 迭代式任务规划

这篇记录复杂任务如何用小步骤、可检查产物和前置确认点替代一次性完整计划。

对复杂任务来说，“先写一份完整计划”很容易变成一种假确定性：模型会把还没验证的信息补齐，把模糊需求过度具体化，然后后面越做越偏。

更稳的方式通常是：

**先定一个很小的下一步。**
比如只要求模型产出“第一版问题拆解”或“下一步要验证的 3 个假设”，不要让它一次性给完整路线图。

**每一步都要求可检查产物。**
不要只说“继续优化”，而是让它给出可以确认的东西：候选方案、表格、接口草案、测试样例、边界条件清单。

**把确认点前置。**
例如：“先不要写代码，先列出你理解的需求和不确定点。”这样能尽早发现它是不是已经脑补了。

**要求它标注确定性。**
让它分清楚“已知事实 / 推测 / 需要用户确认 / 需要查证”。这能显著减少添油加醋。

**限制输出范围。**
比如：“这一步只做数据结构设计，不讨论 UI。”模型很容易扩散，范围越窄越可靠。

一个好用的提示词可以是：

> 我们不要一次性制定完整计划。请采用迭代方式。每次只完成一个小步骤，并在进入下一步前给我一个可确认的中间结果。遇到不确定信息时不要脑补，请列为待确认项。当前先做第一步：复述你对目标的理解，并列出最多 3 个需要确认的问题。

这类方式尤其适合产品设计、代码重构、论文写作、商业方案、数据分析这些容易“看起来很完整、实际漏洞很多”的任务。
